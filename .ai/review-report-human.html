🔴 CRITICAL 级别问题（2项）

CRITICAL-1: hashmap_foreach 迭代期间 rehash 导致 UAF
CRITICAL 并发安全 src/data/hashmap.c:390

问题描述: 回调函数中调用 hashmap_put 触发 rehash，导致 buckets 数组被 realloc，外层 for 循环的 entry 指针变成悬空指针，访问已释放内存导致崩溃或数据损坏。

症状 → 根因链

  • 症状: 回调函数中调用 hashmap_put 导致程序崩溃
  • 直接原因: private_expand_if_necessary 触发 rehash，buckets 数组被 realloc
  • 根本原因: hashmap 未实现迭代期间修改保护（fail-fast iterator 或 copy-on-write）

影响

  • Use-After-Free 导致数据损坏或远程代码执行
  • 生产环境难以复现（依赖特定哈希冲突和负载因子）

修复建议

  • P0-立即: 文档明确禁止在回调中修改 hashmap
  • P0-短期: 实现 rehash 保护（增加 iteration_count 标志）
  • P1-中期: 提供 hashmap_foreach_safe 变体
CRITICAL-2: 数据结构层绕过统一内存管理
CRITICAL 内存安全 + 架构 src/data/{hashmap,list,array}.c

问题描述: hashmap、list、array 等核心容器直接使用 stdlib malloc/free，通过 #undef 绕过 mem_debug.h 的重定向，导致这些模块的内存分配无法被 allocation_tracker 追踪。

影响

  • 内存泄漏检测失效
  • 无法使用自定义分配器（mplite）
  • 内存管理策略不一致
  • 调试困难

修复建议

  • 重构所有容器支持 allocator_t 参数
  • 提供默认实现保持向后兼容
  • CI 检查强制所有源文件包含 mem_debug.h

🟠 HIGH 级别问题（8项）

HIGH-1: hashmap_put 存在 Use-After-Free 风险
HIGH 内存安全 src/data/hashmap.c:294

问题: 先返回 old value 指针，再调用 value_free_fn 释放它
修复: 加强文档 + 提供 hashmap_put_safe 变体

HIGH-2: xlog 全局锁持有时间过长
HIGH 性能 + 并发 src/log/xlog.c:531-643

问题: 全局锁保护整个日志路径（格式化、vsnprintf、fprintf、fflush）
影响: 高并发场景吞吐量严重下降
修复: 异步日志（生产者-消费者模式）+ 线程本地buffer池

HIGH-3: thpool 单队列锁成为并发瓶颈
HIGH 性能 + 并发 src/thread/thpool.c:412-461

问题: 所有 worker 争抢单一 jobqueue 锁
修复: work-stealing 队列 + 无锁队列（MPMC ring buffer）

HIGH-4 ~ HIGH-8: 其他高优先级问题
HIGH
  • HIGH-4: file_logger 职责过载 - 单一模块承担5项职责，依赖7+个模块
  • HIGH-5: 循环依赖风险 - msg_queue_handler → slog → file_logger 可能形成环路
  • HIGH-6: ring_buffer_clear 非线程安全 - 并发调用导致 in/out 不一致
  • HIGH-7: hashmap rehash 内存峰值 2x - 大 map 可能触发 OOM
  • HIGH-8: 核心模块缺少单元测试 - hashmap、array、ring_buffer 无独立测试

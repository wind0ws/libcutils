# 编码规范

## 必须遵守

- **始终首先包含 `common_macro.h`** - 提供跨平台宏和类型定义
- 使用 `EXTERN_C_START`/`EXTERN_C_END` 保持 C++ 兼容(或使用 `extern "C" { ... }`)
- Windows DLL 导出使用 `API_DECLSPEC`
- 调试断言用 `ASSERT()`，关键检查用 `ASSERT_ABORT()`（Release 也会终止）
- 在所有 `.c/.cpp` 源文件第一行包含 `mem/mem_debug.h`，启用内存调试功能, 包括内存泄漏检测和越界访问检查。

## 常用宏

| 宏 | 用途 |
|----|------|
| `ARRAY_LEN(arr)` | 数组长度 |
| `FREE(ptr)` | 安全释放指针并置空 |
| `UNUSED(x)` | 消除未使用的变量警告 |
| `STATIC_ASSERT(expr)` | 编译期断言 |

## CMake 配置要点

- 主 CMakeLists.txt 位于 `tool/` 目录（非项目根目录）
- 项目根目录通过 `get_filename_component(PRJ_ROOT_DIR ${PROJECT_SOURCE_DIR} DIRECTORY)` 获取
- 版本头文件由 `inc/config/` 下的模板生成

## Git 提交规范

提交消息格式：`<type>(<scope>): <subject>`

| type | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `refactor` | 重构（不改变行为） |
| `style` | 格式调整（不影响逻辑） |
| `docs` | 文档变更 |
| `test` | 测试相关 |
| `chore` | 构建/工具链/依赖等杂项 |
| `release` | 版本发布 |

- `scope` 可选，填模块名，如 `fix(file_logger): ...`
- `subject` 用英文，简洁描述做了什么
- **禁止**在提交消息中添加 `Co-authored-by`、`Generated by` 等 AI 署名信息

## AI 工作产物管理（防止 `.ai/` 目录膨胀）

**核心原则**：`.ai/` 不是 AI 的草稿堆。耐久结论沉淀进 `kb/`，过程文件用完即删。

### 目录边界

- **`.ai/kb/`** 是唯一的持久区，只存长期知识：`build.md` / `changelog.md` / `ci.md` / `conventions.md` / `modules.md`。新增持久文件需在 `CLAUDE.md` 知识库索引表登记，否则不要建。
- **`.ai/` 顶层、`docs/plans/`、`docs/superpowers/` 及其他仓库内目录，禁止堆放** plan、review report、verification report、diagnosis、session-summary 等过程产物。这类文件是会话级临时产物，不是项目资产（已在 `.gitignore` 兜底忽略，但仍应遵守优先写到 claude 目录的原则）。

### 结论沉淀去向（耐久内容必须进 `kb/`，不能只留在临时文件里）

| 产出类型 | 沉淀去向 |
|---------|---------|
| 重要修改 / 修复 / 重构结论 | `kb/changelog.md`（追加有序列表项，见 CLAUDE.md 修改规范） |
| 评审发现的**未修复**真实 bug | `kb/changelog.md` 的「开放项移交」中登记（含位置、根因、修复方向、优先级），不得只躺在 review 文件里 |
| 构建 / 工具链 / API / 用法类知识 | 对应 `kb/build.md` / `kb/modules.md` 等 |

### 临时文件生命周期（如果确实需要先写草稿）

1. 临时 plan / review / 分析文件**优先写到 `kb/` 之外的会话临时位置**（如 `~/.claude/plans/`），不要落进受版本控制的 `.ai/`，也不要写进仓库内的 `docs/plans/`、`docs/superpowers/` 等目录（superpowers 等 skill 的默认落点已在 `.gitignore` 兜底忽略，但仍应优先写到 claude 目录）。
2. 若因协作必须放进 `.ai/`：**任务收尾前**把耐久结论转录进 `kb/`，然后**删除该临时文件**（git 已跟踪的用 `git rm`）。
3. **判据**：一个文件若"结论已进 `kb/` 且无人再引用"，即应删除——留着只会误导后续会话、不利维护。
4. 删除前先确认结论确已沉淀（尤其是「未结案的开放 bug 台账」这类内容，丢失代价高）。
